\section{Omega as an auditable folding program}

Omega treats folding as a compilation-and-execution process. A candidate structure is generated by executing an operator program on a discrete state; each operator proposal is evaluated by a readout (e.g., contacts, distogram residuals, or physical gates) and either accepted, rejected or repaired. The full run is recorded as an audit trace containing operator identities, accept/reject decisions, phason violations and repair actions ($\Delta w_0$). This design makes it possible to perform A/B tests on mechanisms (e.g., phason gating, codec expressivity, macro-operator policies) with precise attribution.
